#$ DESCRIPTION: VTX TX power control on the AUX7 switch for a VTX with a THREE level power ladder - the Hummingbird, HummingRoach, AcroB, BardoII, TINYHAWK_II and NANOHAWK family. The switch windows come from the HummingRoach dump of 2026-11-02.
#$ DESCRIPTION: IMPORTANT - the power in a vtx row is an index into that quad's own VTX table, not a universal power level. The CLI checks it against the table: a row power above the table's level count is rejected with "invalid argument count" and the row is cleared. This preset is for the table "vtxtable powervalues 0 1 2" with labels 25 / 100 / MAX - so index 0 is 25 mW, index 1 is 100 mW and index 2 is MAX (200 mW on the quads that label it that way). For the BETAFPV G473 family the same table is "1 2 3 4 0" = 25 / 100 / 200 / 400 / PIT, which is a different preset.
#$ DESCRIPTION: Because a row power of 0 is the firmware's "leave the power as it is" sentinel, 25 mW - which is index 0 on this family - can never be forced by a row. It is the parked value instead: the options set vtx_power = 0, which is 25 mW on this ladder.
#$ DESCRIPTION: At power-up every channel reads midrc (1500) until the radio links, and the rows are evaluated straight away, so any forced row whose range contains 1500 forces its power at every power-up and that value is what gets saved. The options are therefore split around 1500 - levels are forced on either side of it and only the row that contains 1500 is left unmapped. The range boundaries are microseconds but the CLI floors them to 25 us steps and the end of a range is exclusive, so the closest usable boundaries either side of midrc are 1475 and 1525.
#$ DESCRIPTION: Band and channel are left at 0, which the firmware reads as "do not change the current band or channel", so this preset touches neither the band table, the power ladder, nor the selected band/channel - the VTX manufacturer settings are left exactly as configured.
#$ DESCRIPTION: The last option reproduces the captured HummingRoach configuration exactly. It is not boot safe - the 1500 default lands in its 1350-1700 row and forces 100 mW - and its third row uses power 3, which does not exist on a three level table, so the CLI accepts it but the device has no such level.
