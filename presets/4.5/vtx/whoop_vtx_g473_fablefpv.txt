#$ DESCRIPTION: The BETAFPV G473 VTX publishes its ladder as "vtxtable powervalues 1 2 3 4 0" with labels 25 / 100 / 200 / 400 / PIT, so index 1 = 25 mW, 2 = 100 mW, 3 = 200 mW, 4 = 400 mW and 0 = PIT. A row power of 0 is the firmware's "leave the power as it is" sentinel, so PIT cannot be selected by a row at all - it can only be set by hand in the Video Transmitter tab.
#$ DESCRIPTION: Each vtx row sets the TX power for a range of AUX7. The firmware evaluates the rows on every RX frame and writes the matching row power into vtx_power, so an active row always overrides a power set by hand in the Configurator.
#$ DESCRIPTION: The power is an index into the quad's own VTX table, not a universal level, so a preset is valid only for the table family it was written against. The CLI rejects a power above the table's level count with "invalid argument count" and clears that row, so a mismatched preset loses one tier.
#$ DESCRIPTION: The clear option writes the idle form of a row - vtx N 0 0 0 0 900 900 - which is what the firmware stores for an unused slot. A zero-width range never matches and a power of 0 means "leave the power as it is", so the cleared rows cannot touch the TX power. It leaves vtx_band, vtx_channel and vtx_power alone.
#$ DESCRIPTION: At power-up every channel reads midrc (1500) until the radio links, and the rows are evaluated straight away, so any forced row whose range contains 1500 forces its power at every power-up and that value is what gets saved. The range boundaries are in microseconds but the CLI floors them to 25 us steps, and the end of a range is exclusive, so the closest usable boundaries either side of midrc are 1475 and 1525.
#$ DESCRIPTION: Band and channel are left at 0, which the firmware reads as "do not change the current band or channel", so these presets touch neither the band table, the power ladder, nor the selected band/channel - the VTX manufacturer settings are left exactly as configured.
